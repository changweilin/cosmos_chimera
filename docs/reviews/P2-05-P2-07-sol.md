### C1 — medium：空副手集合略過公開 Pre 檢查

**檔案：**[PartnerLoadout.cs:189](../../Assets/_Project/Features/Creatures/Runtime/Model/PartnerLoadout.cs:189)、[PartnerLoadout.cs:199](../../Assets/_Project/Features/Creatures/Runtime/Model/PartnerLoadout.cs:199)

**反例輸入：**

```csharp
var loadout = new PartnerLoadout(new[] { 1 }); // 尚無副手

loadout.ResolveProvisions(1, null, validCreatureOf, validLookup);
loadout.ResolveProvisions(1, "",   validCreatureOf, validLookup);
loadout.ResolveProvisions(1, "a",  validCreatureOf, null);
```

**預期：**契約要求 `mainSpeciesId` 非空、`species != null`；Editor／Development 應拋出 `ContractException`。

**實際：**三者全部正常回傳空集合。檢查被延後至迴圈內的 `Provision.Resolve`；同樣的 `species=null`，有副手時才拋出例外。

**建議修法：**在配置結果集合及進入迴圈前，以 `Contract.Requires` 檢查這兩條無條件 Pre。

### C2 — medium：合法資料的重複素材合計超出執行期表示域

**檔案：**[EvolutionRequirement.cs:55](../../Assets/_Project/Features/Creatures/Api/EvolutionRequirement.cs:55)、[EvolutionRequirement.cs:89](../../Assets/_Project/Features/Creatures/Api/EvolutionRequirement.cs:89)

資料邊界依據：[creature.schema.json:65](../../Data/schemas/creature.schema.json:65)、[validate_data.py:262](../../tools/validate_data.py:262)。

**反例輸入：**非成年型態，下一階段有效，專精包含 fire，素材為：

```json
[
  {"element": "fire", "tier": 1, "qty": 2147483647},
  {"element": "fire", "tier": 1, "qty": 1}
]
```

**預期：**資料驗證階段拒絕無法表示的合計；通過驗證及匯入的資料，應滿足 `FromDef` 的前置條件。

**實際：**

- schema 限制單筆數量，未限制同鍵合計。
- validator 的素材檢查只核對專精屬性；importer 逐筆保留素材。
- `FromDef` 的公開 Pre 未列出合計限制，最後卻觸發建構子的限制。
- 探針結果：Editor 為 `ContractException: summed material quantity overflows int`；Release 為 `OverflowException`。

這不是靜默溢位或部分扣款；問題是資料驗證與執行期接受域不一致。

**建議修法：**validator 與 importer 按 `(element, tier)` 彙總並拒絕合計超過 `int.MaxValue`；同步補上 `FromDef` 的 Pre。保留目前建構子的溢位防線。
