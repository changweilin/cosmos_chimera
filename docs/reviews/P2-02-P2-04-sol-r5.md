## 新發現

### R1 · low · 內殼層落點經 float 捨入後仍無法接續 Overlaps

這是 **Q3 尚未涵蓋的新邊界反例**。

位置：

- [HitVolume.cs:269](/C:/Users/user/Documents/app/cosmos_chimera/Assets/_Project/Features/Combat/Runtime/Model/HitVolume.cs:269)：承諾結果位於接受域，可交給 `Overlaps`。
- [HitVolume.cs:312](/C:/Users/user/Documents/app/cosmos_chimera/Assets/_Project/Features/Combat/Runtime/Model/HitVolume.cs:312)：先 clamp 半徑，再轉回 float 世界座標。
- [HitVolume.cs:479](/C:/Users/user/Documents/app/cosmos_chimera/Assets/_Project/Features/Combat/Runtime/Model/HitVolume.cs:479)：內界只給 `1e-6` 相對餘裕。

使用正式係數、正式 defaults、STR=0：

```csharp
var planet = new PlanetConfig(640f, new float3(16000f));
var arc = MoveGeometry.Build(
    MoveShape.Arc, MoveMovement.None, RangeClass.Mid,
    BurstOrigin.Caster, 12000, 0, stats, defaults);

float3 caster = planet.ToWorld(new float3(1f, 0f, 0f), 0f);
float3 aim = planet.ToWorld(new float3(0f, 1f, 0f), -320f);

float3 landed = MoveGeometry.ResolveAnchor(arc, planet, caster, aim);

MoveGeometry.Overlaps(
    arc, planet, landed, float3.zero, landed, 0f);
```

兩個輸入完全符合**嚴格殼層**，不依賴輸入餘裕：

```text
caster = (16640,16000,16000)    半徑 = 640 m
aim    = (16000,16320,16000)    半徑 = 320 m
```

實測輸出：

```text
landed = (16319.943359375,16006,16000)

落點半徑        = 319.99961438751831 m
接受域內界      = 320 × (1 − 1e-6)
                = 319.99968000000000 m

低於接受域內界  ≈ 0.0656125 mm
```

接續 `Overlaps` 實際拋出：

```text
ContractException:
Precondition failed: anchor must be within R/2..2R
of the planet center (combat shell)
```

原因是 **float 世界座標的捨入誤差取決於世界座標大小**；目前內界餘裕只依 `R/2` 計算。在中心 16 km、內半徑 320 m 時，先 clamp 再轉 float 仍不足以保證結果落在接受域。

這不是單純量測誤差：有效施放產生的 anchor 無法進入後續命中判定，違反公開 Post。修正需讓最終 float 輸出與殼層接受條件相容，並補上上述內殼層回歸。
