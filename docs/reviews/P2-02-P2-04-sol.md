## HitResolver 查核結論

目前實作的控制流程正確：

- 無幾何接觸優先回傳 NoContact。
- 無敵幀回傳 Invulnerable。
- 上述兩條路徑不抽樣。
- 其餘路徑呼叫一次 `NextUInt(1000)`，以嚴格 `< chance` 判定。
- 1000‰ 仍消耗一次 bounded draw，且一定命中。

這裡的「一次」是 **一次 bounded draw**；Pcg32 rejection sampling 可能消耗多個原始步進，與其契約一致。

DerivedStats 的 evasion 曲線上限與 hit_floor 查核通過。修正後 evasion 的整合責任仍屬後續 P2-09，本輪沒有據此推定未實作問題。

## Geometry 發現

### G1 · med · 對蹠點被折疊成距離 0，遠端目標誤判命中

位置：`Runtime/Model/HitVolume.cs:378`–`:388`。

具體輸入：

```text
planet = Radius 640、Center (0,0,0)
anchor = (0,640,0)
target = (0,-640,0)
forward = (0,0,1)
targetRadius = 0
baseRangeMm = 2000、STR = 0
```

對 front、line、sweep、cone、caster burst、ally 分別建立判定體。

**預期：**大圓距離為 `π × 640 ≈ 2010.619 m`，全部不命中。

**實際：**六者全部回傳 `true`。

對蹠點的 cross 與 planar 都為零，但 angle 為 π；`planarLength < 1e-12` 分支直接令 `x=z=0`，將其當成重合點。

**建議修法：**退化分支區分同向與反向。反向不得回傳零距離；圓／ally 可保留大圓距離，方向型形狀則需明訂確定性的對蹠處理。

現有測試沒有對蹠點案例。

### G2 · med · 瞄準對蹠點產生 NaN 落點

位置：`Runtime/Model/HitVolume.cs:253`–`:276`，尤其 `:274`。

具體輸入同 G1，建立：

```text
shape=Arc、rangeClass=Mid
baseRangeMm=12000、STR=0
caster=(0,640,0)、aimPoint=(0,-640,0)
```

**預期：**符合 Pre 的輸入應產生有限落點，距離不超過 12 m，且半徑維持 640 m。

**實際：**

```text

```

對蹠方向減去投影後為零向量，`math.normalize` 產生 NaN。即使施法距離為零，也不能靠 `sin(0)` 消除 NaN。

**建議修法：**在正規化前處理退化 tangent；對反向方向選擇確定性的正交軸，或明訂並檢查排除條件。補上有限值、半徑及距離 Post 測試。
