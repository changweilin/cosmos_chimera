### R4 · low · 非零微小方位仍被折成原點，後方目標誤命中

位置：`HitVolume.cs:459–464`，尤其：

```csharp
if (bearingLength < 1e-12 * rp || distance == 0.0)
{
    return true;
}
```

此處保留 `x = z = 0`。非零距離落入門檻時，後方目標會被當作位於矩形起點。

最小重現，使用正式 balance：

```csharp
var stats = new DerivedStats(BalanceFixture.Coefficients());
var defaults = BalanceFixture.HitDefaults();
var planet = new PlanetConfig(640f, float3.zero);

var front = MoveGeometry.Build(
    MoveShape.Front, MoveMovement.None, RangeClass.Melee,
    BurstOrigin.Caster, 2000, 0, stats, defaults);

bool hit = MoveGeometry.Overlaps(
    front, planet,
    new float3(0f, 640f, 0f),
    new float3(0f, 0f, 1f),
    new float3(0f, 640f, -1e-10f),
    1e-12f);
```

| 項目 | 結果 |
|---|---|
| 真實方位 | 正後方 |
| 測地距離 | 約 `1.00000001335143e-10 m` |
| 目標半徑 | 約 `1e-12 m` |
| 預期 | `false` |
| 實際 | **`true`** |

1° cone 亦可重現。所有輸入符合 Pre。

這是**既有退化策略仍留下的缺陷**，不是證明 double 改寫新引入退化。影響僅奈米級，沒有發現一般戰鬥尺寸的錯誤；但目前 Post 沒有允許將此距離視為零。

**建議修正：** 僅在距離確為零時返回原點；非零方位可從原始叉積建立切向量，避免直接投影 `dp` 的徑向殘差：

```csharp
double3 bearing = math.cross(math.cross(da, dp), up);
double px = math.dot(bearing, right);
double pz = math.dot(bearing, f);
```

再移除非零距離的門檻捷徑。此修正方向已在記憶體內驗證：153/153、原規模探針及 Sector oracle 通過，兩個 R4 見證均改回 `false`。應補正式回歸。
