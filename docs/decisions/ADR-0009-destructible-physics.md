# ADR-0009：可破壞物件的運動用 Unity 剛體物理（主機權威）

## 狀態
已採納（使用者定案：所有場景物件可被攻擊，效果與屬性、材質、質量相關，參考薩爾達傳說；物理深度選「Unity 剛體物理」）。規格見 `docs/design/destructibles.md`。

## 背景
- 架構規則要求戰鬥、生成寫成純 C#，以便 EditMode 測試與主機權威模擬（overview.md）。
- 被打飛、倒塌、翻滾要有薩爾達式的手感；自寫決定性的剛體模擬（堆疊、旋轉、碰撞）成本遠高於收益。
- 球面世界不能用 `Physics.gravity` 表示重力（CLAUDE.md 硬性規則）。

## 決定
1. **拆兩層**：物件的 HP、材質反應、破壞、掉落在規則層（純 C#，決定性）；物件的**運動**交給 Unity 剛體，屬表現層，但只在主機執行。
2. 球面重力：`Physics.gravity = 0`，由元件每個物理步對剛體施加指向球心的力（方向由 `PlanetFrame` 推導）。
3. 物件平常是靜態、沒有剛體；第一次被擊中才喚醒成剛體，穩定後休眠，碎片休眠一段時間後消失。
4. 連線：主機模擬剛體並同步喚醒中物件的位姿；客戶端不模擬。
5. 剛體（被打飛的物件、碎片、地上的素材）不回饋規則層：不阻擋宙獸、不造成傷害；宙獸的表現層帶運動學碰撞體，把它們推開。規則層只看「物件是否完整」（例：建築、樹、岩石破壞後移除阻擋地塊）。素材被拾取或被招式擊中，以規則層的素材表為準（主機權威），不靠剛體碰撞判定——**修訂（`ADR-0010`）**：地上素材在主機剛體休眠時將位置寫回規則層素材表。

## 後果
- 規則層仍可完整測試；剛體行為只能用 PlayMode 測試，且結果不保證跨機器一致——所以不能讓它影響任何規則結果（第 5 條）。
- 網路頻寬隨同時喚醒的剛體數成長；需要上限（同時喚醒數、碎片數），P6 壓力測試納入。
- 之後若要「滾石砸傷宙獸」或「瓦礫擋路」，必須把剛體結果送回規則層（主機權威下可行，但單機與連線要走同一路徑），需另開 ADR。

## 替代方案
- **規則層決定性運動學**（只有滑動擊退、重物不動）：可測、可重現、連線便宜，但沒有翻滾與倒塌手感。使用者未採用。
- **全部剛體常駐**：散佈物件數千個，效能不可行。
