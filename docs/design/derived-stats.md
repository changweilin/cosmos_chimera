## 能力值尺度與製作預算（提議中，待人工確認）

| 階段 | 每項軟設計帶 | 四項總點數 | 均衡錨點 | 可偏科範例 CON/STR/SPI/AGI |
|---|---:|---:|---:|---|
| 幼年 juvenile | 10–50 | 100 | 25 | 40/20/20/20 |
| 少年 adolescent | 25–100 | 200 | 50 | 80/40/40/40 |
| 成年 adult | 50–200 | 400 | 100 | 160/80/80/80 |

這是同階內容製作預算，不是 schema 限制、玩家加點機制或隱藏階段倍率。先固定同階總額，再以同階下界阻止完全棄養一項；特性 / 副手的能力值加成也須納入預算審核。超帶內容需人工檢查，不由參考模型拒絕。
演算法接受 schema 的任意非負整數；每項先取 `x = min(stat, stat_effective_cap)`，有效上限提議為 10,000。這是遠高於成年帶的計算飽和值，不是下一階成長目標；禁止重複疊加倍率繞過它。

## 曲線與係數（提議中，待人工確認）

共同形狀 `S(x; K) = x / (x + K)`：零點連續、單調、邊際收益遞減，`K` 表示取得一半增益的能力值。相比線性，極端數值不會帶來無限血量、速度或射程；相比早期硬截斷，正常設計帶仍有回饋。
所有率以整數千分比表示，單位常數 `P = 1000`；距離為 mm、速度為 mm/s、時間為 ms。`P` 是編碼單位，不是平衡旋鈕。

| JSON 係數 | 提議值 | 含義 / 選擇原因 |
|---|---:|---|
| `model_version` | 1 | 公式 / 取整規約版本；變更需重產黃金向量 |
| `stat_effective_cap` | 10000 | 極端輸入固定飽和，可窮舉有效定義域 |
| `hp.base / gain / half_stat` | 600 / 900 / 100 | 保留底血；總漸近上限 1500，避免 CON 成為無上限的唯一生存解 |
| `melee_volume.gain_permille / half_stat` | 1000 / 100 | 近戰體積最多接近 2 倍，線性尺寸僅接近 1.26 倍 |
| `ranged_distance.gain_permille / half_stat` | 500 / 100 | 射程最多接近 1.5 倍，避免遠程拉開整個戰鬥空間 |
| `ranged_distance.cap_mm` | 36000 | 最終射程硬上限；參考長射程也必須受限 |
| `cd.min_permille / half_stat / floor_ms` | 400 / 100 / 250 | 同時限制相對施招加速與絕對連發頻率 |
| `speed.base_mm_s / gain_mm_s / half_stat` | 4000 / 2000 / 100 | 速度最多接近 6 m/s，避免無限風箏 / 穿越戰場 |
| `evasion.cap_permille / half_stat` | 400 / 150 | 最多 40%，且比速度較晚取得一半收益，抑制 AGI 雙重收益 |
| `hit.floor_permille` | 50 | 幾何碰撞後最低 5% 機會 |
| `reference_move.cooldown_ms / accuracy_percent / base_range_mm` | 2000 / 100 / 24000 | 僅供預設示例、曲線與黃金向量；不取代招式自己的資料 |
| `stage_bands.*` | 見上表 | 製作時的 `min_stat / max_stat / total_stats`，不是執行時階段加成 |

以 `⌊ ⌋` 表示向下取整，`⌈ ⌉` 表示向上取整；以下先使用各自截斷後的 `C/T/S/A`：

```text
HP       = hp.base + floor(hp.gain * C / (C + hp.half_stat))
volume_p = P + floor(melee_volume.gain_permille * T / (T + melee_volume.half_stat))
linear_p = floor_cuberoot(volume_p * P * P)
g_p      = P + floor(ranged_distance.gain_permille * T / (T + ranged_distance.half_stat))
range_mm = min(ranged_distance.cap_mm, floor(move.base_range_mm * g_p / P))
f_p      = P - floor((P - cd.min_permille) * S / (S + cd.half_stat))
CD_ms    = max(cd.floor_ms, ceil(move.cooldown_ms * f_p / P))
speed    = speed.base_mm_s + floor(speed.gain_mm_s * A / (A + speed.half_stat))
evasion_p = floor(evasion.cap_permille * A / (A + evasion.half_stat))
hit_p    = clamp(floor(move.accuracy * (P - evasion_p) / 100), hit.floor_permille, P)
```

`f(SPI) = f_p/P`、遠程 `g(STR) = g_p/P`；近戰的 `g` 則是 `volume_p/P`，**不可當作線性尺寸倍率**。以攻擊原點為縮放中心，近戰判定體各線性尺寸與偏移乘 `linear_p/P`，角度不變，實際體積比例為 `(linear_p/P)^3 ≤ volume_p/P`。體積多量化一次，差異小於約 0.3%；碰撞尺寸轉成整數 mm 時也向下取整。不放大宙獸本體，不提高傷害，不把近戰體積倍率再乘到遠程 AoE 半徑或飛行速度。
`mid / long` 均只延長可達距離 / 最長彈道；AoE 半徑與判定厚度維持招式定義。`dash` 的位移與攻擊判定必須分離，不把體積倍率再乘位移。具體判定體資料與 dash 行為交 P2-01 / P2-04 定義。

射程以球面地表路徑長度解讀；36 m 低於既有 R≈640 m、眼高≈1.7 m 的約 47 m 地平線，留約 23% 餘量。半徑仍只讀 `PlanetConfig.Radius`，不在平衡 JSON 複製。地形、遮蔽或不同攝影機可讓實際可見距離更短，施招端仍須檢查視線 / 可見目標，不能把 36 m 當作「保證看得到」。高度或範圍特性不得略過這個射程上限。
SPI 不縮短前搖、後搖或碰撞生效時間。最短 CD=250 ms 代表每隻最多每秒 4 次 CD 就緒，兩隻最多 8 次；這不是動畫或 AI 可無條件完成的施招率。`cooldown_ms=0` 也得到下限，不表示免 CD。
命中仍是先幾何碰撞再擲骰；此處 `hit_p` 僅為碰撞後的條件機率，accuracy=0 也受 5% 下限。是否碰到、翻滾無敵幀與 RNG 不在參考模型內。

## 玩家能感受到的差異（提議中，待人工確認）

只把某項從 100 提到 200、其餘不變時（敏感度比較，總點數已增加，不是合法同階配點）：

| 能力 | 100 → 200 的結果 | 解讀 |
|---|---|---|
| CON | HP 1050 → 1200 | 可承受傷害 +14.3%，不減免單次傷害 |
| STR | 體積 1.500 → 1.666；線性 1.144 → 1.185；遠程 1.250 → 1.333 | 體積 +11.1%、近戰線性 +3.6%、遠程距離 +6.6% |
| SPI | CD 倍率 0.700 → 0.600；參考 CD 1400 → 1200 ms | CD −14.3%；不受動作限制時施招率 +16.7% |
| AGI | 移速 5.000 → 5.333 m/s；閃避 16.0% → 22.8% | 速度 +6.7%；100% accuracy 的條件命中 84.0% → 77.2%，相對少中 8.1%，擲骰部分等效耐久 +8.8% |

上述成年錨點附近，每點 CON 的相對 HP 邊際收益約 0.214%；每點 SPI 的理論施招率約 0.214%；每點 AGI 的移速與擲骰耐久收益相加約 0.214%。這是選係數的局部尺度，不是把移速當作可直接相加的傷害或存活率。
STR 的價值取決於幾何是否跨過「碰得到」的門檻；對已必中的木樁沒有持續傷害收益，對群體可能命中更多目標。保留這個定位，但需要可見的範圍預覽；不以偷偷加入傷害補償。

## 取整、移植與不變式

決策狀態仍為「提議中，待人工確認」。非負整數除法逐式向下取整；CD 倍率用 `P-floor(reduction)`，使它向上近似未量化的倍率；CD 乘積再向上取整，避免多量化一次提早就緒。`ceil(n/d)=(n+d-1)//d`。命中千分比向下取整後再 clamp，不能先把 accuracy 四捨五入成其他單位。
立方根用整數二分搜尋；`L³ ≤ volume_p×P² < (L+1)³`，禁止浮點 `pow`。先取整倍率，再乘招式資料；合併分式會改變結果。
Python 接受任意大 stat；C# int32 stat 的負值須拒絕，非負值先飽和。所有中間加乘必須**先轉 signed Int64**，最後才轉 int32，不能依賴 int32 溢位後再 clamp。
參考 loader 的可移植係數包絡：所有數字在 0..1,000,000；半飽和值、正基礎值 / 下限 >0；兩個 STR 增益 ≤1000；CD 最小倍率在 1..1000；閃避上限 <1000；命中下限在 1..1000。這是格式 / 算術安全界線，不是建議遊戲數值。
包絡內 `x+K≤2,000,000`、曲線增益乘積 ≤10¹²、move int32×倍率 ≤2,147,483,647×2000、立方根搜尋中間值 ≤2000³；均遠低於 Int64 上限。HP / 移速 ≤2,000,000，距離 ≤1,000,000，CD ≤max(輸入 CD, 下限)，輸出可用 int32。更改單位或放寬包絡需重新證明。

- HP 對 CON、近戰體積 / 線性與遠程射程對 STR、移速 / 閃避對 AGI 單調不減；CD 倍率 / 有效 CD 對 SPI、條件命中對 AGI 單調不增。量化允許平台，不能要求嚴格遞增 / 遞減。
- `hp.base ≤ HP ≤ hp.base+gain`；`1≤V≤2`、`1≤g≤1.5`；`1≤L` 且立方體積不超過 V；射程在 `[0, cap_mm]`。
- `cd.min_permille ≤ f_p ≤ P`；`CD≥cd.floor_ms` 且 `CD≤max(base_cd, floor)`。
- 移速在 `[base, base+gain]`，閃避在 `[0, cap]`，條件命中在 `[hit.floor, P]`。
- 零能力、零威力（本模型不讀）、零 CD、零 accuracy、零射程均不造成除零；非法負值 / 非整數必須失敗。
- stat≥有效上限的結果完全相同；各項只影響指定衍生值；相同資料無隨機性，逐位元重現。

測試窮舉 `0..10000` 的全部有效輸入類別，並驗證飽和尾段、int32 極值、10¹⁰⁰、所有 accuracy 百分比、混合輸入、各取整界線及中間值界限；不把某個平衡數字寫成精確期望值。
[40 組黃金向量](../../tools/balance/golden_derived_stats.json) 是 C# 互通與取整規約的位元基準，另以檔案重產穩定性測試保護；不是平衡定案。公式或係數變動須重新審查 / 產生。
