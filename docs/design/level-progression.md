# 宙獸等級與成長（P2-12）

正式數值：[`Data/balance.json#progression`](../../Data/balance.json)（鍵值見 [balance-keys.md](derived-stats/balance-keys.md#progression)）。C# 實作 `Creatures/Api/Progression.cs`；Python 參考 `tools/balance/level_rewards.py`，兩者以 `tools/balance/golden_level_rewards.json` 黃金向量逐位元核對。`Data/_incoming/p2-12-level-proposal/` 保留提案歷史。

## 已確認規則（2026-11-08）

- 個體等級為整數 **LV1–100**；新取得的初始御三家為 **LV10**。
- 只有 **CON／STR／SPI／AGI** 隨等級成長：LV1 為該型態基準值的 **10%**，LV100 為 **100%**，中間線性插值。
- 屬性、基礎抗性、專精百分比與招式威力只隨型態／招式資料改變，不乘等級倍率。戰鬥中的特性與效果修正仍依 [combat.md](combat.md) 處理。
- 每種宙獸分別指定固定解鎖門檻，不在取得個體時隨機擲骰；幼年 → 少年為 **LV20–30**，少年 → 成年為 **LV35–50**，超載為 **LV60–80**，區間含兩端。
- 升級經驗來源為 **戰鬥、收服、任務、BOSS 戰**；經驗需求採 **指數曲線**。
- 進化以**等級取代舊經驗門檻**，仍需要並消耗屬性素材；進化保留個體等級，不重置經驗。

## 四維縮放

```text
L = 個體等級，1 ≤ L ≤ 100
B = 目前型態的基準 CON／STR／SPI／AGI
倍率 = 0.1 + 0.9 × (L − 1) / 99 = (L + 10) / 110
未取整能力值 = B × (L + 10) / 110
```

LV10 倍率為 18.18…%；LV100 保留完整基準能力值。等級先縮放四維，再交給既有 [衍生值公式](derived-stats.md)，不是把最終 HP、射程、CD、移速或閃避率直接乘倍率；衍生值原有底值與上下限仍適用。

現有 `stats` 作為 LV100 基準；每項四維僅在縮放後四捨五入一次（half up），整數公式為 `(B × (L + 10) + 55) // 110`（Q-C28 已定案）。C# 乘法前提升為 Int64；不先把倍率取整為百分比，避免低等級出現額外階梯。允許基準值 0，亦不另設最小能力值。

## 指數經驗曲線（已定案）

每次升級所需經驗採指數成長；累計經驗為各級需求的總和。首級需求 **100 EXP**、成長比 **105/100**（2026-11-08 使用者確認）。

```text
C(L) = ceil(100 × (105/100)^(L − 1))，1 ≤ L < 100
T(1) = 0
T(L) = sum(C(k), k=1..L−1)
```

每級需求由精確比率獨立計算後向上取整，不以已取整的上一級需求再乘 1.05，避免誤差累積。移植時可使用工具預算的整數門檻表，避免執行期浮點冪次造成跨後端差異。

| 等級 | 累計需求 T(L) | 升至下一級 C(L) |
|---|---|---|
| 1 | 0 | 100 |
| 10 | 1,106 | 156 |
| 20 | 3,062 | 253 |
| 30 | 6,246 | 412 |
| 35 | 8,523 | 526 |
| 50 | 19,867 | 1,093 |
| 60 | 33,609 | 1,779 |
| 80 | 92,442 | 4,721 |
| 100 | 248,528 | 滿級，不再升級 |

## 經驗分配

- **按每隻個體權重**分配：出場過的主力權重 **4**，其餘主力權重 **2**；每一權重單位分到相同經驗。例：總經驗 120、兩隻出場、四隻未出場且全員存活，總權重為 16，出場者各得 30、未出場者各得 15（2026-11-08 使用者確認）。
- **中途替換**不清除已出場標記；換下與後來換上的個體，只要曾出場就各以權重 4 計算，不按上場次數重複加權。
- **死亡個體不取得經驗，且移出分母**，由剩餘存活主力依權重重新分配。若全員死亡，所有主力均為 0，不做除法。例：總經驗 120、兩隻曾出場但其中一隻死亡、四隻未出場，存活出場者得 40，未出場者各得 20。
- **每場戰鬥獨立記錄出場資格**，下一場戰鬥重置，不累計整次星球探索。
- **收服與任務經驗與一般戰鬥相同**（Q-C31，2026-11-09）：收服用擊倒該宙獸那場戰鬥的出場紀錄；任務步驟用完成它的那場戰鬥的紀錄（擊倒／收服觸發），由抵達區域完成的步驟用進行中的戰鬥紀錄，沒有戰鬥時全員以後備權重 2 計。紀錄在擊倒時快照，之後的戰鬥不會改寫它。
- **升級效果在戰鬥結束後結算**（Q-C31）：戰鬥中只累計經驗；該場結束後，存活主力的四維、HP 上限與 STR 判定體依新等級重算，已受的傷害保留（HP 增加量等於 HP 上限增加量）。戰鬥中倒下者本 run 維持原等級（D0 不復活），經驗仍寫回存檔。
- 副手可以取得經驗與升級，取代 Q-C10 原「副手不升級、不成長」；副手經驗以所屬主力實得經驗的一半為基準。
- 副手組**共分** floor(主力實得 / 2)，額外發放、不扣主力池；整數結算與滿級規則見 [獎勵量](#獎勵量q-c29q-c30-定案)（Q-C30 定案 2026-11-09）。
- 經驗成長不等於自動進化；進化仍只在大廳執行且檢查素材。副手換型態後，必須重新驗證「副手階段 ≤ 主力階段」，不得沿用「副手不成長所以搭配永遠成立」的推論。

```text
E = 該事件的主力經驗總量
w(i) = 死亡時為 0；存活且曾出場為 4；其餘存活主力為 2
W = sum(w(i))
主力 i 經驗 = W > 0 時 E × w(i) / W，否則為 0
```

`allocate_main_xp` 使用精確分數；整數結算採最大餘額法（見下節），存檔只存整數累計經驗。

## 獎勵量（Q-C29／Q-C30 定案）

**2026-11-09 使用者定案：方案 A**（SOL 提案）。替代方案 B（依型態階梯、BOSS 另加野戰、副手各拿一半）未採用，原文見 [rewards.json](../../Data/_incoming/p2-12-level-proposal/rewards.json) `options.B`。

`d=1..10` 為提議新增的星球難度，不由半徑或屬性推定；目前資料沒有此欄，D0 六種星球一律以 `d=1` 校準。`t=0..2` 直接取 `RunRegion.Tier`；`s=0/1/2` 為實際幼年／少年／成年型態。`H(s)=[10,20,35]`；`clamp` 限制在 LV1–100。`C(L)`、`T(L)` 沿用已定案曲線，`C(10)=156`。

**方案 A（定案）**

| 項目 | 數值與公式 | 取捨 |
|---|---|---|
| 來源主力池 | 基數 `b`：野戰 80、收服 40、任務每步 80、整鏈額外 160、BOSS 640；`E=floor(b×C(min(L,99))×r/156)`；野戰菁英 `r=2`，其餘 `r=1` | 隨敵等級與需求曲線成長，型態階段不再乘一次倍率。 |
| BOSS／收服 | BOSS **只發 BOSS 池**，不另發普通野戰；成功收服另發收服池，BOSS 收服也只用基數 40 | 排除戰鬥重複計價，仍獎勵成功收集。 |
| 野生／新收服 | `L=clamp(10+10(d−1)+2t+角色加成)`；普通／菁英／BOSS 加成 `0/3/5`；收服保留型態及 L，`Exp=T(L)` | 難度與等級一致；既有成年型態可能低等級，進化等級只限制往後進化。 |
| 舊存檔 | 一次版本遷移：`Exp新=T(H(s))`；先備份舊值，不把舊進化計數當成累計升級 XP | 避免誤讀舊語意，但舊 Exp 不折抵成長。 |
| LV100 主力 | `Exp新=min(T(100),Exp舊+實發)`；滿級仍保留 4／2 權重，分到的份額與跨級溢出丟棄，不囤積 | 不會把滿級隊友變成集中灌經驗工具，但會浪費份額。 |
| 主力整數結算 | 精確權重分數先取 floor，再按小數餘額由大到小補到 E；同餘額按永久 instance ID 小者優先 | 有存活者時整數池守恆；固定 ID 在重複平手時略有優勢。 |
| 副手 | 主力實得 `a`＝整數結算且套滿級上限後實際增加的 XP；**副手組共分** `floor(a/2)`，以同一最大餘額法均分存活副手；額外發行，不扣主力池 | 無論掛幾隻，副手合計最多多發主力實得的 50%。 |
| 副手滿級／損失 | 死亡副手移出組分母；存活滿級副手保留份額但丟棄，不轉給其他副手；奇數 a 的半點丟棄；全滅時整個 E 丟棄 | 所有損失列入帳本，不暗中重分配或跨事件存分數。 |

A 的 L：擊倒／收服取原遭遇等級；任務步驟取目標區域普通野生等級；整鏈取 BOSS 等級。D0 普通 t0／1／2 為 LV10／12／14，t1 菁英 LV15、BOSS LV19。

遷移後 `OwnedCreature.Exp` 只表示累計升級 XP，已轉換版本不得再加起始值；輸入已超滿級時先規整至 T(100)，不當成本事件實得。

共同給獎邊界：每個 spawn 的擊倒只發一次；成功收服只發一次，失敗為 0。每事件取事前名冊與獨立參與紀錄，死亡在結算時判定；新收服者到大廳才加入收款名冊，不能領自己的收服獎勵。副手 instance ID 不得同時是主力或隸屬多個主力。任務每步只獎勵真正達成的條件；完整 5 步才發整鏈額外獎勵。D0 提早擊倒 BOSS 會跳過剩餘步驟，跳過步驟與不完整鏈均不給獎，不能只根據 StepIndex 的跳動發錢。

**D0 校準依據與假設**

唯讀核對 `Bootstrap/Demo/*.cs`、`RunPlanner.Generate/Sites/Weight`、`QuestTracker`、`Data/_demo`、`Data/balance.json`：六種星球，D0 小／中 R640 生成 12 區、大 R1280 生成 32 區；每個非 BOSS 區 2–3 群，t0 每群 1–2 隻、t1／2 每群 1–3 隻；路線中間區各 1 菁英（至少 1），**1 BOSS、1 鏈、5 步**（到點 → 同指定屬性擊倒 3 隻 → 指定菁英 → 收服 1 隻 → BOSS）。全圖生成數不是必打數；BOSS 沒有任務鎖，能直接結束 run。以下是 2026-11-09 定案前的校準模型，非實測遊玩紀錄／戰鬥時間預測。

非御三家池 7 線共 21 型態，每階 7 隻（木水火土金冰風）；青翠星 3 個偏好屬性權重各 3、其餘各 1，指定屬性機率 `3/13`，三次命中平均需 **13 隻普通敵人**。模型採 t0／1／2 各 **4／6／3 隻**、t1 成年菁英 **1 隻**、成年 BOSS **1 隻**；共 15 隻擊倒，不主張每 seed 都相同。曦影星偏好光／影不在野生池，指定屬性步驟目前無法命中，仍可殺 BOSS 結束，因此本校準明確使用青翠星完整任務路線（此問題已由 RunPlanner v2 修正，P3-10）。

普通收服率 60%（不含豐饒詞綴）、BOSS 100%；每隻倒下後 20 秒內只能投一次。固定代表結果為投普通 4 次成功 2 次＋BOSS 成功 1 次，共 **3 次成功收服**（相同期望值為 `4×3/5+1=17/5`，沒有拿期望值假裝整數成功數）。正常完成 **5 步＋1 鏈**；兩次普通收服均取 t1 少年。捕獲個體進倉庫，不改本 run 名冊。
